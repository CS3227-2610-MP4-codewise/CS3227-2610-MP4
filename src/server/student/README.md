# Student service boundary - Keith

Student dashboard reads, durable working copies, atomic submission, attempt history and the C-SUB producer (`D1SubmissionCatalog`). Frontend screens belong under `src/web/student/`. Released feedback is read through the C-REL producer (below); progress requests are a later change. Use shared contracts and the common database; do not create duplicate assignments, users or assessment tables. Never return unreleased assessment drafts or private reference solutions to students.

Specs: `openspec/specs/student-submissions` (SW-01-SW-11, C-SUB SUB-C01-C06, K4); `student-dashboard` for the read routes; `openspec/changes/student-released-feedback` (SF-01-SF-08) for feedback. Shapes are the closed `schemaVersion 1` schemas in `src/shared/student-work.ts`, `src/shared/student-assignments.ts` and `src/shared/student-feedback.ts`.

## Routes (`studentHandler`, wired in `src/server/index.ts`)

Every route needs a trusted session. Every mutation also needs the origin and CSRF check (`requireMutationOrigin`); a port without it fails closed. Every response is `Cache-Control: no-store`. Denied and missing objects (other student, instructor, outsider, revoked member, foreign or cross-course ID) share one 404 body.

Bodies carry `code`, a fixed message and a request ID only; a revision conflict also carries the caller's own current row.

## Rules the code keeps

- **Authority where data is written or disclosed.** Reads embed `currentStudentGuard`. A save is one statement whose WHERE clause contains the guard. Move and submit are D1 batches that start with `currentStudentWriteGuard` (a `course_write_guards` row computed in SQL), so a revocation, republish or deadline between the confirmation and the write aborts the whole batch.
- **Server clock.** `StudentWork` reads its injected `clock()` once per request. A submit is accepted only when `now < deadline_at` (ISO strings); client time is neither accepted (closed schema) nor used.
- **Idempotency.** The key is scoped to (user, assignment). The replay lookup is membership-guarded and runs before the batch, so the same key and fingerprint returns the original even after the deadline, and a former member gets 404. A different fingerprint is 409. Racing replays hit the UNIQUE constraint and re-read.
- **Rate limit (SW-11).** Per account: 12 draft saves and 3 new submits per fixed 60 s window, through the existing D1 limiter `AuthStore.rate` (`rate-limit.ts`, composed in `src/server/index.ts`). Counted after the session check; for submit, after the replay lookup, so a same-key retry is never limited. Over the limit: 429 `RATE_LIMITED`, nothing written. Not a cap on attempts (SW-07). Move is not limited. Each counted request writes a limiter row as well.
- **Fingerprint.** SHA-256 of canonical JSON `{publicationId, answers:[[questionVersionId, draftRevision, sourceHash]...]}` sorted by question version.
- **No execution.** Source is stored and returned as text only.

## C-REL consumer (released feedback)

`feedback.ts` (`StudentFeedback`) consumes `StudentReleasePort` (`attemptReleases`, `getAuthorized`, `currentness` of `ReleaseReadPort`), passed to `studentHandler` as a per-request factory. Order per request: session (401); the existing guarded own-attempt read (uniform 404 before any producer call); `attemptReleases`; `getAuthorized`; `assertCurrentRelease`; then `currentness` again, and any token change is 409 `STALE_FEEDBACK` with no content. Producer `FORBIDDEN`/`NOT_FOUND` become 404, `STALE_EVIDENCE` becomes 409, anything else (including a producer contract breach) 503, with no producer detail in the body. Version states (`released`, `superseded`, `withdrawn`) come from the producer's currentness projection, the same rule the producer uses for one version. No cache, no stored copy and no read of assessment tables. `release-port.ts` (`studentReleasePort`, composed in `index.ts`) supplies Darryl's real producer, `AssessmentService.consumer`, with student read ports: object reads of an `assessment` or `submission` require the caller's own attempt and current Student membership (one SQL check with `currentStudentGuard`; the assessment's attempt and course come from `AssessmentRepository.scope`), and the submission read is `StudentWork.attempt`. The instructor workflow's ports are unchanged; it authorizes instructors only. Real D1 only, never loopback samples. Without the port the routes return 503 and history markers are `false`. `feedback.test.ts` runs against `FakeReleasePort` (fixture runs); `release-port.test.ts` runs the routes against the real composed producer and instructor workflow on local D1. Darryl's review of the producer change and this adapter is pending (Ownership.md, 2026-11-12 extension).

## C-SUB producer

`D1SubmissionCatalog` (`catalog.ts`) implements `SubmissionCatalog` with `sampleMode=false`. It checks current Instructor membership in SQL, validates attempts with `validateAttempt`, lists a student only when their latest attempt for the whole assignment (ordered by `submitted_at`, then insert sequence) is on that exact publication; more than 1,000 rows fails closed. It uses an opaque per-course label (`Student` plus 8 hex of a hash) and reports malformed stored data as `UPSTREAM_UNAVAILABLE`. It never reads `student_drafts`. It is not composed in `index.ts` yet (task 6.2, Darryl's seam).
