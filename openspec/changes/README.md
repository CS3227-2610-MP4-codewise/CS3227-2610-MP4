# Bounded feature changes

codewise-mvp/ is the in-flight overall plan. Its requirements are not proof of completed services.

Create smaller changes when scope and owner are agreed. Suggested names are darryl-instructor-assignments, keith-student-submissions and shared-authentication. Use openspec new change through the installed workflow rather than hand-creating directories. Each change has the proposal, specs, design and tasks required by its schema. Reference the relevant MVP requirement IDs and reconcile overlapping contracts before integration.

Feature-change directories are not created ahead of planning: empty scaffolds can fail the validate-all check. Store verification in workflow/evidence/<change>/, transition details in workflow/handoffs/, and interaction summaries in logs/<owner>/. Archive only completed changes using OpenSpec.
