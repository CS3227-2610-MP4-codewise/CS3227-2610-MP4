# Design

Use the existing gateway and authoritative assessment, publication and submission ports. Resolve current object and course access for generation, candidate reads and adoption. Bind exact question, rubric, submission and explicitly selected versioned instructor references into the evidence and request fingerprint. Treat all context as untrusted data and never execute submitted code. Bound serialized input and output through gateway limits.

Store a private candidate with model and prompt provenance without changing the assessment head. Validate exact coverage, scores and source excerpts before persistence and again before adoption. Adoption rechecks evidence and authorization and atomically compares the expected head, preserving immutable revisions and released history. Never approve or release automatically. Preserve unsaved browser edits and reject stale asynchronous responses.

Follow warm-workbook-v1 tokens, focus and announcement behavior, source-linked observations, narrow layout and both appearances; disclose no execution. No intentional design departures. No production provider activation or student-side implementation is authorized by this change. Keep synthetic and live integration evidence separate.
