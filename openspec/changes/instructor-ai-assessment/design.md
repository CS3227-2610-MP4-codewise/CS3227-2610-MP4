# Design

Use the existing gateway and authoritative assessment, publication and submission ports. Resolve current object and course access for generation, candidate reads and adoption. Bind exact question, rubric, submission and explicitly selected versioned instructor references into the evidence and request fingerprint. Treat all context as untrusted data and never execute submitted code. Bound serialized input and output through gateway limits.

Store a private candidate with model and prompt provenance without changing the assessment head. Validate exact coverage, scores and source excerpts before persistence and again before adoption. Adoption rechecks evidence and authorization and atomically compares the expected head, preserving immutable revisions and released history. Never approve or release automatically. Preserve unsaved browser edits and reject stale asynchronous responses.

Follow warm-workbook-v1 tokens, focus and announcement behavior, source-linked observations, narrow layout and both appearances; disclose no execution. No intentional design departures. No production provider activation or student-side implementation is authorized by this change. Keep synthetic and live integration evidence separate.

## Offline restart recovery continuation — 2026-11-12

AI-02/03/05 and GRADE-01–04: before dispatch, bind the actor, course, assessment, expected revision, evidence fingerprint, reference selection and idempotency key in a guarded D1 write. A recovery read selects the newest successful gateway request associated with the current authorized actor and revision, reruns gateway authorization and validation, and does not materialize a candidate; gateway reads may conservatively expire request and lease bookkeeping. If a recovered result has not yet become a candidate, an explicit, origin-checked adoption validates it again and stores the candidate using the existing guarded writer before the revision transaction. Existing persisted candidates remain supported. This binds the request without storing source or prompts in the new association. Unknown provider work remains conservatively charged and cannot be cleared based solely on a local timeout; provider evidence is required for reconciliation.

The explicit resume control uses an authenticated, origin-checked POST to reissue the exact bound idempotency key and reference selection; it may dispatch only if the gateway request was never begun. Concurrent resumes converge on the gateway's persisted idempotency record. Pending/unknown state leaves manual grading available, and UI text tells the instructor resumption can send a saved request. Distinct overlapping keys for the same actor, assessment and revision are blocked while an earlier binding is unstarted or the gateway is pending/running. An old request delayed before its initial server binding can still arrive after a newer request has completed; user-action ordering is not guaranteed across such independent requests. ## 2026-11-13 blank-source safeguard

A live synthetic blank answer received maximum scores with contradictory explanations and reference attribution. For safety, instructor AI generation fails closed before binding or provider dispatch whenever any pinned answer is empty or whitespace-only; the resolver independently applies the same rule on later reads/recovery. This does not assign scores, decide how partial work should be graded, or modify manual assessment/approval/release. Existing AI candidates for blank submissions are no longer disclosed through this resolver. This is a narrow availability tradeoff, not proof of overall semantic accuracy. [AI-02/05, GRADE-01/02]

For the repeated Q2 contradiction, the prompt now generally requires numeric scores to agree with their explanations and forbids awarding full credit while explaining failure. This does not change the rubric or expected scores; only a live rerun can assess the effect. [GRADE-02, AI-02/05]
The model also attributed feedback to the private reference in Q4. The assessment prompt explicitly forbids quoting or revealing reference solutions in feedback and asks it to cite submitted source only; this instruction is not a deterministic privacy guarantee and must be evaluated. [AI-02/05]
