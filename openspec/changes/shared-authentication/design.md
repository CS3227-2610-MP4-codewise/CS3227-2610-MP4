# Shared authentication design

## Context

Approved policy is recorded in the proposal/member log; the final approval additionally includes in-app invitation administration with manually copied/sent links, superseding the earlier proposal's CLI-only administration exclusion. Base2d8a861, matching codex/shared-authentication; only the pre-existing untracked member log was present. No real SH-AUTH/SH-ID producer yet. Reuse C-ID sessionViewSchema, TrustedPrincipal and IdentityCoursePort semantics. Darryl's exact approved write window is in Ownership; Keith's revised-boundary review remains pending.

## Goals / Non-Goals

Implement SHA-01–07 with an authoritative D1 auth store and real maintained provider adapter. No Keith course/membership/object producer, role/self-promotion, application passwords, automatic mail, provider-global logout, live deployment or broader instructor-feature wiring. No generic personal/orchestration files enter Git. UI uses docs/ui/design.md warm-workbook-v1 and existing primitives without adding a design framework.

## Decisions

- Provider: fixed Google discovery/issuer and configured client/origin; pinned openid-client6.8.9 uses code+S256 PKCE, state, expected nonce and ID-token validation. Only openid/email scopes. Tokens exist only during callback; no provider refresh/token session store. Provider adapter is injectable for protocol tests but deployed composition never injects synthetic identity. Missing/invalid configuration returns unavailable and disables sign-in.
- Public HTTP: GET /api/auth/bootstrap supplies pre-auth CSRF capability and cookie; POST /api/auth/login initiates a browser-bound10-minute transaction. GET /api/auth/callback validates and consumes it once; callback immediately redirects to a clean fixed local finish URL. GET /api/auth/session supplies a separate role-free auth UI envelope containing the unchanged sessionView, contact email, auth-admin presentation flag and session CSRF. POST /api/auth/logout revokes. Auth endpoints are intentional public exceptions; protected feature routes remain unavailable.
- Cookies: production uses __Host- prefixed Secure/HttpOnly/Path=/, SameSite=Lax; development uses separately named loopback-only insecure cookies under explicit development config. No Domain, browser storage or auth-bearing query in generated invitations. Invitation links use a fragment; UI clears it immediately into in-memory state and sends it only in the same-origin login POST. Link-scanner GETs do not consume invites. Responses/pages are no-store/no-referrer, callbacks never log URLs/provider payloads.
- CSRF: derive a domain-separated HMAC from the opaque HttpOnly bearer, returned only by same-origin bootstrap/session JSON; verify request header with native crypto plus exact configured Origin. No global signing secret or raw CSRF store needed. Public bootstrap rejects foreign Origin/Fetch-Site. Cookie capability is not an identity unless its hash resolves to an active DB session.
- Store: additive0003 owns auth_accounts (unique canonical issuer/sub, active flag), auth_sessions (hashed bearer, internal ID, creation/last-seen/absolute expiry/revocation), auth_invites (hashed bearer, intended email, creator, expiry/accepted account/revoked status), auth_transactions (hashed state and browser binder, nonce/verifier, invite hash, return path, expiry/consumed), auth_administrators (existing account FK) and bounded auth rate-limit buckets. No course or instructor-role tables. Raw invite is shown/copied once on creation; list contains status only. Auth-admin boolean is presentation, never authority.
- Atomic callback: consume transaction conditionally before token exchange; a failed exchange stays consumed and requires a new login. Commit onboarding and session insertion in one D1 transaction with constraints/triggers that abort on unavailable invitation, stale admin-created admission, competing issuer/sub, email mismatch or inactive account. Existing issuer/sub signs in without re-registration, but disabled accounts never use a new invite to reactivate. Current account/admin state is rechecked at mutation commit. Parameterized queries and guarded inserts do not silently create partial results.
- Sessions: random256-bit bearer, SHA256 at rest, separate internal principal handle. Current session rotates on sign-in and old request session is revoked in the same batch where present. Idle30min/absolute8h are enforced in every lookup and conditional touch. Logout/revoke-all/account disable cannot race a touch into revival; subsequent requests always query current DB authority. Expired transaction/rate/session rows have bounded cleanup. Rate-limit login starts and invitation creation before expensive/network work; do not log raw IP identifiers.
- Trusted operations: a local operator helper can create the first invitation and grant/revoke auth-admin to an existing verified issuer/subject. It requires an explicit local database target and refuses email-only/client-role elevation. It runs outside web requests and does not perform remote changes without separately authorized release/operator work. Admin UI creates ordinary account invitations only; cannot grant itself auth-admin or course rights. Revocation/list/create reauthorize in D1 on every operation.
- Safe handoff: retain allowlisted /workspace and existing-format instructor assignment destination IDs only after strict URL parsing; reject scheme-relative, external, encoded/backslash/control/double-encoded ambiguous forms. Store return path in the login transaction and session; callback always goes to /auth/finish. The workspace endpoint calls a narrow injected destination authorizer built from Keith's existing course/object methods before returning an approved local destination. Default missing producer returns unavailable, not a redirect to unimplemented routes. No account/session store duplication in role services.
- UI: quiet two-part sign-in, Continue with Google and invitation explanation, exact pending/cancel/error/session-expired states. Signed-in unavailable screen provides identity/logout; invitation management appears only when authenticated admin state is projected, while server checks remain authoritative. Native labelled email form,24-hour status rows, copy-once result and explicit revoke; no role picker or email-send promise. Manual checks cover320/768/1024/1440, appearances, keyboard, text sizing and live/synthetic distinctions.

## Verification and risks

Actual local-D1 tests cover migration/FK/uniqueness, concurrent invites/callbacks, rollback, disabled/revoked/race/expiry, hashes/cookie flags/CSRF, admin denial and callback replay. Real OIDC adapter tests use signed synthetic issuer responses and mock transport, not a synthetic principal fallback; verify mismatched issuer/audience/signature/nonce/PKCE and cancellation. Reusable C-ID producer checks run against real session storage with fake Keith authorization explicitly labelled. Existing instructor tests continue unchanged.

Missing Google client credentials/approved callback origins prevent live verification; record pending, never expose a fake production login. Existing deployed environments require reviewed migration/config and provider setup through release workflow; no deployment is authorized here. New schema is additive; rollback retains account/session records and revokes active sessions rather than inventing incompatible stores. Invitation delivery is manual, copy-later is deliberately unavailable because only hashes persist.
