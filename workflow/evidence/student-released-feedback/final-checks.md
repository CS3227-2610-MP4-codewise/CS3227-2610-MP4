## Findings returned to Keith

**S1. Medium, OPS-01/resource: feedback reads are not rate-limited.**

- One released-feedback open costs about 33 production D1 queries and 2 Firebase account lookups (estimated; [read-cost](read-cost.md)).
- A signed-in student running a scripted loop could drain the Workers Free daily D1 and request quotas for everyone.
- Design D2 chose "no rate limit beyond the existing reads", and the existing student reads are unlimited too; feedback is simply the most expensive of them.
- **Options:**
  1. reuse the SW-11 per-account limiter (`AuthStore.rate`) for the two feedback routes, which costs one limiter write per counted request;
  2. accept the risk for the class deployment and record it;
  3. defer to a shared rate-limit change.
- No code changed.

**S2. Informational, accepted design: `attemptReleases` skips the evidence-digest check.** It discloses only metadata (assessment ID, currentness, version numbers) after the batched ownership check. Content reads keep the full evidence check. This was agreed by Darryl in the Ownership.md amendment.

**S3. Informational, evidence hygiene:** the UI review agent's `ui-review/check.txt` contained one local home-directory path, which is now redacted to `~`.
