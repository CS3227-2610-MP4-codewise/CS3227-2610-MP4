## Findings returned to Keith

**F1 — Low severity — UI-07: focus-only heading fails the literal 44×44 `[tabindex]` check.**

Reproduce: start the harness; open `http://127.0.0.1:5189/index.html?state=released&theme=light`; set viewport to 320 CSS px at 100%. Measure `.cw-wb-attempt h3[tabindex="-1"]` using `getBoundingClientRect()`. Expected under the explicitly requested “every button, select, a and [tabindex]” rule: width and height ≥44 px. Actual: **288×22 px**. At 768, 1024 and 1440 px it measures **736×22**, **992×22** and **1216×22** respectively. Repeats in both themes and every open-attempt state (96 instances); history has no such heading. [Raw target measurements](ui-review/metrics.json), [narrow screenshot](ui-review/screenshots/320-light-released.png).

This is a heading focus destination rather than a clickable/tappable action, and it is excluded from sequential Tab navigation by `tabindex=-1`; all actionable controls pass. The severity is low for that reason. Return to Keith to resolve the literal review criterion versus this focus-only element; this review neither fixes it nor records a design exception or acceptance.

**Resolution (Keith, 2026-11-12): not applicable.** UI-07's 44 px minimum applies to touch and pointer targets. This heading has `tabindex="-1"`: it is a programmatic focus destination, not in Tab order and not clickable. It also predates this change (`6d79f7e`, student-drafts). The review brief's "every `[tabindex]`" selector over-included it. No code change.

No other product failures were measured in the scoped automated checks. Unverified manual/integration checks remain open.
