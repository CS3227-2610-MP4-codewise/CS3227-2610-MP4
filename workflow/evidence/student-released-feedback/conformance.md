## Finding for Darryl (suite, not producer)

`releaseContractSuite` was **not invoked directly** with the real values. When it was tried, one check failed: "rejects revoked currentness and historical withdrawal never clears a newer current release".

- **Cause:** the suite derives its later snapshots with hard-coded `availabilityRevision` 2, 3 and 4, and expects revision 2 to change the token of its input snapshot. The real producer increments `availabilityRevision` on approval as well as on release, so its first-release snapshot is already revision 2. The precondition "revision 2 is newer" does not hold, and `assertCurrentRelease(release, {...current, availabilityRevision: 2}, token)` does not throw.
- **Producer behaviour is correct:** `verifyAssessmentProducer` independently checked that the real token changes at every transition.
- **Suggested fix (Darryl's file):** derive the later revisions from `f.current.availabilityRevision + 1, + 2, + 3`. The suite's properties were run as explicit checks on real values instead (rows 3–4 above). The suite still runs unchanged against its synthetic fixtures in `src/shared/instructor-contracts/contracts.test.ts`.
